## What changed since the morning's build (run 257's installer)

* **The TM catalogue** (`docs/tm-catalogue-20261031.md`): the Game Corner's TM counter sells every TM of the Gen 1-6
  games, 168 in all (TM51-TM168 are new, PC only), in four kinds - PHYSICAL ATTACKS, SPECIAL ATTACKS, STATUS & SETUP,
  DEFENSE & UTILITY - at the owner's five prices (1,000 / 2,500 / 5,000 / 7,500 / 10,000 coins; the five old TM prizes
  keep their prices), all from the start. Each row shows the TM's number, move, type and price; the Classic 2D shop's box
  names the move and its type; a TM is bought once and never used up. A TM teaches a Pokemon that learned the move by TM
  in any Gen 1-6 game (the owner's rule; Ferroseed and Ferrothorn also get Stealth Rock, the owner's extension). TMs
  past TM50 are kept in a new 36-byte record of the save; an older save loads unchanged.

  BATTLE ITEMS, MEGA STONES (the dealer's list, with a MEGA RING), EVOLUTION & FORMS, POKé BALLS, HEALING, BERRIES,
  TRAINING, TMs (the catalogue) and OTHER: the 249 RARE GOODS at their prices, unchanged, and 199 items found elsewhere
  in the game at the approved prices (the Master Ball 200,000 coins and buyable again, Rare Candy and Ability Capsule
  5,000, Bottle Cap 2,500, the vitamins 300, competitive staples 10,000, the Town Map 1,000). No price sold before
  changed; the casino's bets and payouts are as before.
* **The Emerald Expansion features report** the owner asked for, separate from the above:
  `docs/expansion-features-20261031.md`.
* The launcher's save checker knows the TM record: a save holding a TM past TM50 needs this build's launcher, so
  everyone in a world updates together (as with the Battle Tower's record before).

## The installation check's first attempt (run 262)

Everything in it passed up to the friend's Join Friend: the silent install, the files, start, repair and uninstall;
Create World through the menu window; both players' characters from the New Game; the host's Solo world and Host World
(entered, played, saved). Then the friend typed the host's invite code and chose Check and join: the friend's menu
showed the character entering the host's world and "Waiting for you to stand in the field ... Choose CONTINUE", and the
friend's game started and connected to the friend's companion (its output is in the job's log) - but the check found no
window for that game in 90 s and failed ("friend: no game window opened (last screen busy)").

The check passes over every game it has seen before by its process number, and Windows gives a new process the number
of one that has ended; the friend's only earlier game (the New Game) had ended. That would explain it, but the job's log
cannot show the game's number, so it is not proven. App `620503c` changes the check for the next runs: an earlier game
is passed over only while it still has its window, and a missed window lists the launcher's processes. The re-run of
run 262 used the check as it was at `8f88e54`, with the same installer, and **passed**: every step, the friend's Join
Friend included (00:57 UTC). The friend's games there had the numbers 5528, 1352 and 1452, none an earlier one's, so
the re-run says nothing either way about the explanation above.
