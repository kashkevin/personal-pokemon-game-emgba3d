# Durable development native battle admission

`BattleJournal` records an unresolved ABI2/3 native battle **before its first BIND**. It reuses the existing checkpoint client, canonical battler descriptor, native codec and atomic private-file helpers. It is an admission foundation, with no result, settlement, restart reconciliation or intent-clearing API. The current actual-core happy-path proof uses the volatile lifecycle separately; it does not establish acceptance of this durable journal through a complete battle.

Construct `BattleJournal(companion, private_directory)` for an authenticated ownership-profile companion with the development ABI2/3 channel explicitly enabled. Phase3 requires ABI3, exactly four trainers and a matching canonical descriptor mode. Enter `async with journal.bind_intent(binding, bind_command, canonical) as intent`, then dispatch `await companion.battle_rpc(intent.bind)` inside that context. The shared character lock remains held across dispatch. Only the exact persisted BIND is authorized; PREPARE, START, KEEP, ABORT and RELEASE require a future durable lifecycle coordinator.

Under that lock, admission owns direct companion mutations before awaiting the current authenticated checkpoint revision, full-container SHA256, build, rules and save profile. It verifies those against the captured canonical descriptor and fences world, player, server epoch, lease, ROM incarnation and companion runtime UUID before and after the network await. It repeats the check for exact uncertain-BIND retries. BIND authority remains absent until durable publication. A canonical descriptor does not prove the live party: native PREPARE must still perform its actual party/counter/trainer comparison.

The bounded, duplicate-free versioned JSON intent contains those identities, battle UUID, immutable generation and the exact 240-byte BIND. A checksummed envelope detects malformed or changed local data. File data is fsynced before exclusive same-directory hard-link publication; existing intent files are never overwritten. Cancellation, lost acknowledgments, failed publication synchronization or abrupt process exit preserve the intent. This requires a private filesystem supporting atomic hard links. The envelope contains no player credential and does not attest a hostile client.

An unresolved intent, including a malformed, unreadable, directory or dangling path, blocks ordinary checkpoint/ownership mutations, trade mutations, save-mailbox writes and unrelated native controls. A generic current save-owner task cannot bypass it. Cold startup refuses before any canonical restore or recovery ACK. Known pending ordinary export or trade files in another registered private directory also prevent BIND admission; changing coordinators cannot discard that known recovery owner. No user directories are scanned.

Direct observational checkpoint info/read, trade status/pending and native/save QUERY remain available. Changed lease, world, process runtime or ROM incarnation refuses exact BIND replay and retains the old intent. An inactive native query, disconnect or timeout never establishes release, forfeit or an authoritative result.

Before player-facing integration, the durable coordinator must extend the journal through preparation, routing, abort/return and both release acknowledgments; define authoritative interruption/result recovery; integrate server arbitration across battle/trade/checkpoint lifecycles; and provide explicit closed-core reconciliation. This module deliberately cannot clear an unresolved battle to launch a new core. Existing teams, four-human battles, rewards, wagers and Championship requirements remain in the master specification.

Focused tests cover real companion TCP/IPC guards and heartbeat continuity, authenticated current-head checks, stale/session-changed admission, cross-directory export recovery, strict malformed intent rejection, exclusive publication failures, cancellation and an actual killed child process after durable intent. These tests establish admission policy and retained evidence, rather than playable battle completion.

On October 8, 2026, the final affected group passed **138 tests on each system**, with zero skips: Windows 37.577 seconds and WSL 42.867 seconds. It includes the 24 new journal/admission cases and existing live checkpoint/trade, cold startup, autosave, companion IPC and runtime lifecycle regressions. Independent source review confirmed the current-head, prepublication mutation and known export-path fences. No actual game ROM or private source save was modified, and no public listener was opened.
