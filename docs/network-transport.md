# Opt-in encrypted multiplayer transport

The Python world server and companion support TLS as a transport foundation. This does not establish Internet delivery acceptance: no router/firewall changes, public listener, friend invitation UI, certificate installer, or separate-PC test was performed. The existing loopback/LAN development mode remains the default.

`secure_transport.ServerTlsConfig(certificate_path, private_key_path)` loads supplied host PEM files. `ClientTlsConfig(trusted_certificate_path, certificate_sha256)` trusts the supplied certificate file and checks the exact SHA256 of the server's DER leaf certificate. Contexts use `SSLContext(PROTOCOL_TLS_SERVER/CLIENT)`, a TLS 1.2 minimum, and bounded handshake/shutdown timeouts. The client retains `CERT_REQUIRED` and certificate validity checks; hostname checking is disabled deliberately because the exact certificate pin identifies the host independently of its numeric IP. No system certificate roots or environment-driven key logging are loaded. The implementation follows [Python's SSL documentation](https://docs.python.org/3/library/ssl.html).

The companion verifies the TLS chain and pin before constructing or transmitting its credential-bearing hello. TLS does not replace player credentials, durable leases, build/ruleset/save-profile checks, or the saved world's UUID. `expected_world_id` independently rejects a different authenticated world at welcome. A certificate change requires an explicit new trusted certificate/pin; there is no automatic trust discovery or plaintext fallback.

Use the programmatic transport API:

```python
from emerald_multiplayer.companion import CompanionConfig
from emerald_multiplayer.secure_transport import ClientTlsConfig, ServerTlsConfig

server_tls = ServerTlsConfig(host_certificate_path, host_private_key_path)
await server.start("192.168.1.20", 8765, tls=server_tls, public=True)

client_tls = ClientTlsConfig(invited_certificate_path, invited_der_sha256)
config = CompanionConfig(
    rom_path, manifest_path, player_id, display_name, ipc_token,
    server_host="192.168.1.20", server_port=8765,
    server_credential=player_credential, server_tls=client_tls,
    public_server=True, expected_world_id=invited_world_id,
)
```

`public=True` enables Internet-source peers only with TLS and an authenticated `CheckpointStore` (including ownership/trade stores). It requires a specific numeric unicast bind address, which can be the host's private LAN IP behind a router. `public_server=True` similarly requires TLS and a player credential. Wildcards, hostnames, multicast, and unspecified destinations are refused. These opt-ins merely configure application transport; they do not forward a port or add a firewall rule. TLS can also be used on loopback without enabling public mode. The legacy command-line entry points remain local/LAN development tools; a launcher must supply the authenticated TLS configuration.

The host keeps its unencrypted private key in a private local location, outside Git/shared bundles. Friends receive the public certificate, DER pin, world UUID, and their own separate player credentials through an authenticated invitation flow, which remains to be implemented. Host key generation, protected key storage, renewal/rotation, usable invitation errors, and distribution are still pending. Never deploy the publicly known test fixture keys.

Asyncio performs TLS during connection establishment, with separate bounded TLS and application hello timeouts; shutdown is also bounded. There is no opportunistic upgrade. See [Python's asyncio stream documentation](https://docs.python.org/3/library/asyncio-stream.html). The application still caps admitted players and post-handshake pending hellos. TLS sockets awaiting handshake are outside that application cap; broader connection-rate/denial-of-service hardening remains a deployment concern.

`tests/test_secure_transport.py` uses real loopback TLS sockets and two disposable valid identities plus one expired identity, generated by the installed OpenSSL 3.0.13 CLI. Their embedded private keys are explicitly public, test-only fixtures. No third-party Python dependency or real host secret is included. Tests cover exact pin and dedicated trust, minimum TLS policy/key-log refusal, malformed configuration, wrong/untrusted/expired certificates before credentials, plaintext refusal, bounded stalled handshakes, authenticated checkpoints/heartbeats, durable restart/lease fencing, and host identity versus world identity. These are transport tests with synthetic ROM/save fixtures, not actual multiplayer gameplay or Internet acceptance.

On October 8, 2026, all 14 transport tests passed on Windows Python 3.14.4 (3.584 seconds) and WSL Python 3.12.3 (8.752 seconds), with no skips. The combined transport/server/companion/checkpoint-server regression passed 56 tests on each OS (21.280 seconds Windows; 56.722 seconds WSL). Only numeric loopback sockets were opened, including tests of the explicit public-mode policy on a loopback bind.
