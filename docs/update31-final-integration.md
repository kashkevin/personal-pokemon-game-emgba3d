**The missing database:** `tests/fixtures/compat/shared_world_u14/world.sqlite3.shared-world.sqlite3`, the shared-world
sidecar as the **Update 14** code (`e2a40d7`) writes it: tables `appearances, clock, coop_results, event_reports,
event_resolutions, events, frontier_attempts, frontier_records, frontier_runs, hall_of_fame, kv, league_records, metadata,
secret_bases` (+ `sqlite_sequence`); records: three World Events (ABSOL caught by player A, GROUDON caught by B, a Mega
VENUSAUR claimed by A but not caught), their reports and resolutions, the world clock, seven `kv` scheduler rows, the world
ID and scope. All identities are synthetic (`aaaaaaaa-…`, `bbbbbbbb-…`). No save, ROM, asset, credential or licensed
material. It is a **test-only fixture**, not game data. Cause: the `*.sqlite3` ignore rule (`df49ecd`, 2026-10-15 03:59) predates
the fixture commit (`69680bb`, 14:29 the same day), so `git add` skipped the file silently; earlier sessions passed only because
the file stayed on their machines. On a fresh clone 4 tests failed and **2 more passed vacuously** (SQLite opens a missing file
as an empty database).

**Resolution** (`claude/fix-compat-fixture`): the generator pins the wall clock and seeds the old code's unseeded generators,
and writes the database as SQL text (`world.sqlite3.shared-world.sql`, 56 lines); regenerating from commit `e2a40d7` reproduces
it byte for byte. The tests build the database from that SQL in a temporary folder, **fail** (never skip) when it is missing,
check its Update 14 format and records, and regenerate it from `e2a40d7` when the clone has that history (skipped only in a
shallow clone). Results: 8 passed, 0 skipped; with the SQL removed, all 8 fail; with one value changed, the reproduction test fails.

## 4. Bugs found and fixed in this integration

| ID | Severity | Bug | Fix |
| --- | --- | --- | --- |
| U31-1 | Medium (tests) | the Update 14 fixture database was never committed (section 2) | SQL text fixture, deterministic generator, fail-when-missing tests |
| U31-6 | High (hang) | the full app suite **hung forever** in `test_launcher_menu` (py-spy): the Tk thread waited in `Thread.start()` inside a Tk callback while the starting thread, running the cyclic GC in its bootstrap, freed a tkinter `Variable` whose `__del__` hands a Tcl call to the Tk thread. Pre-existing (launcher code of Update 28), timing-dependent; it can also hit the launcher fallback window | `tk_threads.start_thread` pauses the collector during `start()` only; all 7 thread starts in the Tk modules use it; `tests/test_tk_threads.py` pins the guard and fails if a Tk module starts a thread directly |
| U31-7 | Medium (Windows test harness) | on Windows SDL2's `SDL_getenv` returns one static buffer that the next call overwrites; the debug scene's name turned into the next variable's value, so **no debug scene started on the Windows build** (found under Wine) | the harness copies each value. The same pattern exists in `bfx_game.c` / `gl_battle.c` for developer tuning variables only (`PKMN_BATTLEFX_*`, `PKMN_DIORAMA_*`), which players never set; documented, not changed |
| U31-8 | Medium (memory) | AddressSanitizer: a following Pokemon read past `sAnim_GoNorth2F` after a script pushed the player back into it (`SetStepAnimHandleAlternation` sought the previous, longer animation's position in a shorter one). **Pre-existing**: Route 101's vanilla push-back triggers it offline; Update 31's gate scene uses the same push-back | an out-of-range position starts the animation at its first frame (PC only); Route 101 push-back under ASan 1 report -> 0; `--selftest-rival` checks every follower walk animation with carried positions 0..15 and fails with the fix disabled |
| U31-9 | Medium (memory) | AddressSanitizer: `ScrCmd_applymovement`'s follower check and `DespawnOWEOnBattleStart` indexed `gObjectEvents[OBJECT_EVENTS_COUNT]` when the object does not exist (`VAR_LAST_TALKED` is 0 after a coordinate trigger, e.g. every original rival battle); a match on those bytes would have written through a garbage sprite index or set a garbage flag. **Pre-existing** (upstream; same class as N22) | both skip a missing object (PC only); the original Route 110 scene under ASan: only N23 remains |
| tooling | Low | `rival_check` / `save_safety_check` key scripts longer than the harness's 64 entries were cut silently | the tools refuse more than 64 entries |

No crash, deadlock or save corruption was observed in the game itself. The memory errors above were out-of-bounds **reads**
found by AddressSanitizer; none was observed as a crash in a normal build.

## 6. Save and data safety

On copies only: the save written by the streamlined introduction passes the app's save validator and Update 30's draft
acceptance (container, source inventory, party 1); it loads through the real title screen and CONTINUE in the **Update 30
build**, the integration's Classic 2D build and its 3D build, unchanged by loading; 12 starts killed at random moments
(SIGTERM/SIGKILL) leave it byte-identical and loadable; a malformed `pokeemerald.cfg` (random bytes, truncated, absurd
values) neither stops the game nor touches the save; faults injected into the save write (process killed after half the
temporary file, killed after the temporary file is complete but before it replaces the save, a short write) leave the previous
save byte for byte and loadable; without a fault the new save replaces it and is valid. Update 31 adds no save field (it uses
the original story flags and variables; `check-abi` layout parity OK); the world gets a new sidecar database
(`<world>.rival-checkpoints.sqlite3`) created on first open, its persistence covered by `tests/test_rival_checkpoints.py`.
Not done: loading the owner's real saves (not available, and never used destructively); saves from much older builds than
Update 30 at the engine level (the app-level compat tests cover the Update 14 world database).
