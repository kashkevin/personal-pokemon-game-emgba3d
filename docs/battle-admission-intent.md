# Original provisional battle admission

`battle_admission_intent.py` records the original local runtime before a resumable battle has its complete host-issued BIND. The frozen `BattleAdmissionIntent` contains the original world/player/build/rules/save-profile/server-epoch/lease/incarnation/runtime pins, exact canonical revision and SHA-256, immutable canonical accepted-challenge bytes, and the exact out-of-band ADMIT19 control. That control carries the generation, local player and native runtime UUIDs. Its envelope fixes the original lease, incarnation, battle, phase, local slot and sequence. Every original participant must already have consented, and the local accepted canonical descriptor must match the trusted roster.

The pure `create_admission_intent` constructor requires the authenticated ABI3/resume1 bridge and original incarnation/runtime. It performs no network request, filesystem write or native operation; callers still own current-head verification and dispatch. The `challenge` property returns a fresh parsed object, preserving the stored consent bytes. `read_admission_intent` checks the bounded canonical envelope, digest, exact fields, scalar types and control correlation. Nonregular files, duplicate JSON keys, oversized or malformed metadata and contradictory identities are refused.

`publish_admission_intent` creates `pending-battle-admission.json` through an exclusive same-directory atomic publication and directory sync. Another unresolved intent is never overwritten. An exact retry preserves the original bytes and repeats directory sync, including after an uncertain earlier publication. The native response has its own client-owned receipt; this module never dispatches, acknowledges, renews, converts to full BIND, settles a battle or deletes either intent. Those operations and pending-lifecycle recognition belong to the separate production client integration.

This adapts the project's existing [BIND journal](native-battle-admission.md), challenge validator, canonical roster, ADMIT codec and durable-file helpers. The engine/upstream/community research remains in [native battle execution](native-battle-execution.md#research-and-reuse) and the [reuse audit](customization-and-reuse.md). No external implementation, dependency, save layout or gameplay rule is introduced.

All **eight provisional intent methods passed** with fourteen recovery-client methods in a clean **22/22 Windows focus in 7.822 seconds**, with no skips. The retained private `integrated-terminal-windows-2.log` has SHA-256 `c5da0708f56eff0c0b96756ec9ea98f92d93f18f34d8e73aff3c138ef4e4609e`. These cover strict original identity/consent, immutable challenge copies, exclusive and competing publication, exact retry, failed directory durability, malformed metadata and read bounds. They are metadata/durability tests, not actual-core provisional hold or playable recovery acceptance.
