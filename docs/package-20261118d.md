## What changed since run 486's build

* **A world whose port another program holds says so when it is played** (KNOWN_ISSUES MS-257; app `d07bd1a`): the
  first entry's setup already said "This world's port is already in use on this PC: close the running host, or the
  other program using that port, then try again."; playing the world afterwards with the port taken said only "The game
  could not open... Reason: OSError" (found on Windows by `installed-world-check` run 46, WinError 10048 at the hosting
  session's bind). The session now gives the same words, with the address and port in the troubleshooting file; any
  other failure keeps the general message. Nothing was ever lost: once the port is free the world plays on.
* The installation check's new steps, in `windows-package` for the first time: the world's port taken as the character
  first enters and as the world is played (MS-257), another installed version refused at Check and join both ways
  (MS-28), the save copies kept to the newest 40 (MS-216), every normal close's statuses read (MS-259); the Tower's
  `duo-presses` (MS-258); the 3D interface audit's guard for states a fix took away (MS-246). Scripts and workflows the
  package does not carry.
