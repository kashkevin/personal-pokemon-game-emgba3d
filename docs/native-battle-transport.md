# Development native battle transport

The compiler-derived battle marker now distinguishes ABI1 diagnostic builds from ABI2 native-singles development builds. The manifest generator reads the marker from the exact ROM at its ELF allocation, accepts only versions 1 or 2, and preserves the same 512-byte mailbox. Runtime manifest validation compares that version to the actual ROM. Lua advertises the configured version and rejects a mailbox with a different header or out-of-range state. An ABI1 build cannot accept phase2 commands. ABI2 retains phase1 diagnostics unchanged.

`native_battle.py` provides separate immutable `NativeBinding`, `Preparation`, `NativeControl` and `NativeQuery` codecs for the [native singles contract](native-singles-prototype.md). The ABI1 diagnostic codecs retain their previous phase, command and block restrictions. The new classes validate the exact 240-byte envelope, zero padding, chunk CRC, correlation fields, two-person roster, authenticated local lease/incarnation, exact operation lengths, fixed native block sizes, sequential 128-byte chunk boundaries and exact peer acknowledgment mask. PREPARE requires a nonzero issued 16-byte RNG state and an acknowledged revision. Responses must confirm that revision, preparation/start flags and the exact generation/local role. Release admits only a normalized fixed-side win/loss/draw result.

The codec validates allocation envelopes, not complete native controller contents. Accepting a 200-byte party block does not authenticate its Pokémon. A battle coordinator must assemble exact startup blocks, compare them to canonical trainer/party data, enforce participant consent and ordered delivery, and apply the audited stateful controller allowlist before routing. The C endpoint independently validates native payloads before dispatch. Neither arbitrary addresses nor generic memory/controller commands are exposed by this transport.

`Companion.battle_rpc` remains explicitly disabled unless `development_battle_channel=True` and a durable authenticated world is configured. It accepts native controls only with a verified ABI2 manifest and matching bridge capability. Existing pending-trade and live-save lifecycle checks still fence mutators; read-only QUERY can inspect uncertain holds. There is one pending RPC, and malformed, mismatched or disconnected responses fail the request. The Lua bridge writes only the existing mailbox command generation/slot and keeps the original 256-byte frame bound. It publishes native READ responses in the same 240-byte control, including the final 72-byte party chunk; it does not add an external write window.

On October 8, 2026, all **50 battle codec/manifest/Lua/socket tests passed** on Windows (5.447 seconds) and WSL (4.813 seconds). Seventeen new cases cover native envelopes, exact party chunk lengths, ABI derivation/downgrade refusal, source roles, preparation flags, response corruption and bounded Lua writes. Test ROMs and mailboxes are synthetic; this result establishes transport validation, not actual native battles, a server challenge menu, full-six-per-trainer Multi or Internet acceptance. The engine adapter and server battle coordinator remain separate integration work.
