# Development native battle transport

The compiler-derived battle marker distinguishes ABI1 diagnostic, ABI2 native-singles and ABI3 full-party Multi development builds. The manifest generator reads versions 1–3 from the exact ROM at its ELF allocation and preserves the same 512-byte mailbox. Runtime validation compares that version to the actual ROM. Lua advertises the exact configured version and rejects a different header or out-of-range state. ABI1 accepts only phase1; ABI2 retains phase1 and adds phase2 singles; ABI3 retains both and adds phase3 with exactly four trainers.

`native_battle.py` provides separate immutable `NativeBinding`, `Preparation`, `NativeControl` and `NativeQuery` codecs for the [native singles contract](native-singles-prototype.md) and its four-trainer Multi extension. The ABI1 diagnostic codecs retain their previous phase, command and block restrictions. The new classes validate the exact 240-byte envelope, zero padding, chunk CRC, correlation fields, exact two- or four-person roster for the selected phase, authenticated local lease/incarnation, exact operation lengths, fixed native block sizes, sequential 128-byte chunk boundaries and exact peer acknowledgment mask. PREPARE requires a nonzero issued 16-byte RNG state and an acknowledged revision. Responses must confirm that revision, preparation/start flags and the exact generation/local role. Release admits only a normalized fixed-side win/loss/draw result.

The codec validates allocation envelopes, not complete native controller contents. Accepting a 200-byte party block does not authenticate its Pokémon. A battle coordinator must assemble exact startup blocks, compare them to canonical trainer/party data, enforce participant consent and ordered delivery, and apply the audited stateful controller allowlist before routing. The C endpoint independently validates native payloads before dispatch. Neither arbitrary addresses nor generic memory/controller commands are exposed by this transport.

`CanonicalBattler` now supplies the read-only checkpoint comparison: it verifies the Flash checksum, ownership world/player, build/rules/profile and full-container hash before deriving the original six-slot party, native counter, trainer ID and exact 28-byte trainer descriptor. All 600 party bytes, including empty-slot tails, must match startup. Header fields have separate bounded validation, and RNG must equal the issued 16-byte state. Current lease and canonical-head checks remain the coordinator's responsibility.

`ControllerValidator` mirrors the pinned native schema from engine source `21c76faa948b3879d5ba7f4085b345f90f8fa166`, independently reviewed against the ARM compiler's numeric layout, with explicit mode-dependent participant bounds. It checks master/owner roles, reply-before-DONE and every renderer's completion; exact command lengths and zero padding; allowed SetMonData fields; Pokémon, move, item, type and ability bounds; bounded text expansion and ROM string-table entries; and animation/party-choice bitfields. String lengths come from the already verified ROM and its matching ELF table allocation, never network input. C performs its own validation before dispatch. These bounds must be audited again when the engine schema changes.

The [session-local BattleDesk](native-battle-desk.md) supplies consent, canonical-head fences, startup and result/release barriers. It has no public endpoint or durable restart recovery. The actual-core coordinator remains an explicit development proof until its transport, persistent mutation guards and player interface are integrated.

`Companion.battle_rpc` remains explicitly disabled unless `development_battle_channel=True` and a durable authenticated world is configured. It accepts native controls only with a verified ABI2/3 manifest, a supported phase and matching bridge capability. Existing pending-trade and live-save lifecycle checks still fence mutators; read-only QUERY can inspect uncertain holds. There is one pending RPC, and malformed, mismatched or disconnected responses fail the request. The Lua bridge writes only the existing mailbox command generation/slot and keeps the original 256-byte frame bound. It publishes native READ responses in the same 240-byte control, including the final 72-byte party chunk; it does not add an external write window.

## ABI3 full-party Multi contract

The optional `mode=3` binding requires four distinct trainers and four leases/incarnations, with local slot 0–3. Fixed teams are slots 0/2 and 1/3. Each source owns the battler with its slot number and its own six-slot, 600-byte party. The canonical descriptor retains native Emerald version `0x4003`, but uses `LINKTYPE_MULTI_BATTLE` (`0x2255`) and its exact source ID; singles retains `0x2211`. Phase/count mismatches are rejected before routing. The original ownership/save profile and Pokémon sizes do not change.

Control/query/preparation sizes, typed block sizes, 128-byte chunking, opcode meanings and lifecycle flags remain unchanged. ACK requires all three peers and excludes the source; RECEIVE permits any other bound source. The query mask is bounded to four participants. The controller validator takes an explicit mode, bounds every consumed battler index to that mode, requires each owner reply, and retains a request until **all four** renderer DONE records arrive. Full-party switch indexes remain 0–5. Multi move selection requires the native double-battle flag and permits target slots 0–3. The native cancel-partner action (12) stays refused; native fainted action replies 13/14 remain supported.

The durable admission journal now accepts phase3 only on ABI3, verifies the canonical descriptor's mode, and persists the exact four-trainer BIND. Its unresolved-intent and exact-task restrictions remain unchanged. The server-owned [BattleDesk](native-battle-desk.md) now requires four independent consents and all-four registration, preparation, startup, restored-result and release barriers. Its [server arbitration adapter](native-battle-arbitration.md) reserves all four participants on the first BIND intent until the final required abort or release acknowledgment. These service and codec tests do not establish native four-core gameplay, durable settlement or recovery.

The final affected codec/roster/controller/manifest/Lua/socket/journal group passed **111 tests per system**, without skips: Windows 16.324 seconds and WSL 16.368 seconds. It includes all prior singles/diagnostic checks, every four-party owner/DONE barrier, full-party switch/target bounds, ABI downgrade refusal and real companion journal admission over TCP/IPC. The first test iteration caught a missing-capability nil comparison in Lua and a new test helper's static-method binding; both were corrected before acceptance. Native four-core Multi gameplay remains a separate acceptance gate.
