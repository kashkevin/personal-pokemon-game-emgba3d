## First pilot implementation

The new `multiplayer_static_reset.c` adapter selects one exact New Mauville Voltorb object. Its own `MP_LOCAL_RESET_NEW_MAUVILLE_PILOT` flag defaults to zero, separately from `MP_LOCAL_RESET_DEVELOPMENT`. The script begins the guarded attempt immediately before its unchanged native `setwildbattle SPECIES_VOLTORB, 25`; failed admission leaves the ordinary encounter intact. The shared reset core still requires enrollment, an idle bound connection, an unchanged roster, a usable party and no network battle. An explicit accepted-reset result branches immediately after native battle return and before the original defeat/removal branches. It ends the authored interaction without restoring a character snapshot or jumping back into generation.

The selected object's native local ID is **6**, at map coordinates **25,18**, using `NewMauville_Inside_EventScript_Voltorb1` and `FLAG_HIDE_NEW_MAUVILLE_VOLTORB_1`; IDs 7 and 8 remain excluded. Admission requires the exact map, talked-to object, active local object at those coordinates, an already-open native door state (generator state 1 or 2), and neither the hide nor defeat flag. Before presenting or accepting reset, the adapter rechecks those fields, the counter version/value and the captured generator/blue/green variables. Clone-based inspection requires an actual non-egg level-25 Voltorb and no additional opponent. Wrong species, level, eggs, malformed records and changed state cannot open the reset window.

The unchanged resume script first reapplies the existing blue/green barrier state and removes the talked-to object only for `B_OUTCOME_CAUGHT`. The accepted reset uses the existing internal cleanup sentinel plus its separate, consumed reset result; that sentinel cannot reach Voltorb's ordinary defeated/teleported branch. The new neutral branch writes no defeat, hide, generator or barrier state. The existing temporary object-control flag is cleared as before. Normal outcomes retain their original branches. Nonaccepted scripted exits now clear the in-memory reset context before the ordinary whiteout/field return, preventing a stale attempt from surviving into another encounter.

Keep the original generation, moves, IVs, shiny calculation, level, catch behavior and prerequisites unchanged. Preserve the existing first-action guard, confirmation, no rollback, connection checks and capture fence. Nonreset battle outcomes must execute the original script exactly. Entry effects that change protected inventory/party state remain ineligible rather than being undone.

Rayquaza illustrates why the return branch is mandatory: its ordinary script treats outcomes outside won/ran/teleported as progression, and other branches remove the object. A local quit disguised as an ordinary outcome can silently defeat or hide the target. Mew and Southern Island additionally change movement and encounter state before entry, making them poor first adapters.

## Counter/storage boundary

The development implementation uses global persistent vars `0x40F7–0x40FA` for a two-word attempt counter, magic and capture flag. Production descriptors cannot share those values or reinterpret existing development saves as species-specific history. Only 18 other persistent vars are named `VAR_UNUSED_*` before reference auditing, so a blanket two-word counter per encounter already needs a broader storage plan. Names alone do not establish that a variable is unused by scripts or configuration.

The pilot reserves three existing Hoenn words: `VAR_MP_VOLTORB_1_RESET_VERSION` (`0x40FB`), `VAR_MP_VOLTORB_1_RESET_COUNT_LO` (`0x40FC`) and `VAR_MP_VOLTORB_1_RESET_COUNT_HI` (`0x40FD`). Version 1 is `0x5601`; only an all-zero legacy record initializes lazily. Unknown versions, a nonzero count with zero version, and counter overflow refuse reset without clearing any data. The development counter/capture fields never become Voltorb history. Broader durable attempts still need the previously identified idempotent checkpoint/journal design; the RAM counter persists on the next ordinary Save and is not crash-durable. No save layout, save ABI, canonical database schema, hunt probability or cooldown changes.

The reference audit across `include`, `src`, `data` and `test` found `0x40FB–0x40FF` only in Hoenn definitions and FRLG aliases, plus the range end. Inspection of native dynamic access found object-graphics offsets in their designated range, temporary rotating-gate bytes, special-variable spray offsets, fixed fan-club/size-record fields and generic script/debug access. No production dynamic caller was found targeting the three reserved Hoenn words. Debug variable editing can still write arbitrary values and is not a compatibility guarantee. FRLG aliases are untouched and this Hoenn-only pilot does not qualify alternate configurations or foreign saves; unknown nonzero data deliberately refuses admission.

The maintained RHH source was rechecked at [`12f292fe14871ca54bc2d73279912a17a921f24b`](https://github.com/rh-hideout/pokeemerald-expansion/blob/12f292fe14871ca54bc2d73279912a17a921f24b/data/maps/NewMauville_Inside/scripts.inc): the relevant generator, availability, resume and removal logic is still supplied by the engine. Its [variable definitions](https://github.com/rh-hideout/pokeemerald-expansion/blob/12f292fe14871ca54bc2d73279912a17a921f24b/include/constants/vars.h) also leave this tail unused. Prior maintained-upstream/community reset research remains applicable: conventional whole-emulator reset cannot supply the required local ownership boundary. The custom code therefore composes the already-qualified local-reset guard with this one authored script. No external code, assets, dependency or license obligation is added; existing engine attribution applies.

## Durable admission implementation

The isolated native worktree is `/home/kevin/src/pokemon/engine-local-reset-delivery`, beginning at preserved `de4ef98a`. Native source `5d02ddad3a` added a dedicated pre-generation mailbox. ABI2 and the nine-source catalogue follow in `3dcfd103f17424c1a5b2278c178f8342078d9676`; see the [current delivery evidence](local-reset-durable-admission.md). Source pins and fixtures alone are not gameplay acceptance.

The authored Voltorb1 interaction suspends its script before `setwildbattle`. A fixed 32-byte request identifies its native sequence, current session/incarnation, compiled descriptor `0x1001`, and the last observed count. The companion uses the authenticated world connection to durably admit that exact attempt. The host response contains only the assigned count; no PID, species override, seed, shiny value, reward or pointer crosses this channel. Only the exact native request acknowledgment resumes generation. An explicit refusal follows the neutral script return, while an unknown outcome or changed binding remains paused. The original per-core RNG continues advancing and the attempt counter never seeds it.

The new `personal_reset_attempts` table lives inside the same world SQLite database and its ordinary backups. The optional extension adds 200 to schema 2/3, composing with the existing 100-point battle reservation extension: 202/203 without battle reservations and 302/303 with both. Migration requires an idle store and a new, reopened, logically verified backup; merely opening a legacy world never migrates it. Fresh world creation enables the table only when its verified ROM manifest advertises reset ABI 1 or 2, retaining a private pre-extension backup and the same accounts/world identity. A verified battle-execution capability similarly enables the battle extension in newly created worlds, with its own backup; existing worlds remain unchanged.

An attempt begins at durable admission of the player's explicit authored interaction, before native generation. Retries with the same request and native identity return the same number. A lost acknowledgment can therefore leave an admitted attempt that was not yet displayed, but cannot lose its number or manufacture another count through transport retry. After a process/host restart the host ledger remains authoritative, including when the latest ordinary native save contains an older count. A saved counter ahead of the ledger refuses entry and requires explicit reconciliation; it is never used to silently rewrite host history. Battle reservations, unsettled committed trades, in-progress uploads and active trade proposals fence admission. This ledger does not change the character checkpoint or confer any capture ownership.

The capability is a separate 128-byte EWRAM mailbox with a ROM ABI marker. Lua permits writes only to its 32-byte acknowledgment and seqlock; it validates exact allocation/marker, padding, identity and monotonic sequence. `Q` advertises the optional capability, `T` carries the native request, and `U` carries the acknowledgment. The existing four-frame reliable queue is retained, with capability announcements deferred until capacity exists. This is separate from the existing `H` IPC authentication handshake.

New rolls for the admitted personal source use the Gen 6 16-value shiny xor range (1/4,096 for a uniform roll), written through the engine's existing shiny modifier. Existing stored Pokémon and the global eight-value display predicate are preserved. Force-shiny/force-not-shiny flags remain authoritative. Unrelated lure, fishing and DexNav modifiers do not enter this personal static generation path; the future personal Shiny Charm remains separate work. The current maintained upstream was rechecked at `7b95be15d84a053948791ce91e5dec0b168947a5`: its [shiny constant](https://github.com/rh-hideout/pokeemerald-expansion/blob/7b95be15d84a053948791ce91e5dec0b168947a5/include/constants/pokemon.h) remains 8. The Gen 6 range follows the prior [primary format audit](https://github.com/kwsch/PKHeX/blob/66ef5983a5d349efa2dd615f2926a1b1ee97306e/PKHeX.Core/PKM/Shared/G6PKM.cs). No community implementation or new dependency is imported.

The qualified nine-source extension and visible count supersede the initial single-source limitation. Remaining acceptance includes ordinary-route entry, reset/reinteraction/capture and fresh Continue, Windows input, the composed pending-reset host-loss lifecycle and simultaneous battle/trade/reset matrix. Dynamic cave movement, seven Kecleon visibility paths and personal Lugia have [source-only adapters](local-reset-expanded-sources.md); the remaining authored Ho-Oh, Mew, Deoxys and Southern Island scripts have a [subsequent source-only extension](local-reset-ticket-sources.md).
