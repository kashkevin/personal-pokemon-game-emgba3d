# Native emergency preservation and retained-core controller

The accepted host-loss policy is to save and disconnect, preserving an interrupted multiplayer battle until every participant reconnects. The original ABI1 prototype below supplies an idle-bound native primitive. The later ABI2/controller section records exact interrupted-export promotion, local durability and one actual-core recovery proof. Launcher activation requires the matching verified ABI2 build; earlier preview packages remain unchanged. A rejected or unsafe save must remain visibly **unsaved and held**, with the process retained; it must not be described as a completed save or silently closed.

## Reuse audit and source boundary

The isolated native worktree starts from `84a4d1c1e906bd7340b9d08b231e485b0fa5c07c`, preserving the qualified Players/Multi source and all private proof inputs. The existing project serializer, ownership allocation, command mailbox, CRC/read window and callback/clock holds supply the implementation. No external code, assets, runtime or dependency is added. Existing save bytes and ownership schemas remain unchanged.

The audit also checked maintained [RHH save source](https://github.com/rh-hideout/pokeemerald-expansion/blob/master/src/save.c), [RHH main loop](https://github.com/rh-hideout/pokeemerald-expansion/blob/master/src/main.c), and the official [mGBA scripting API](https://mgba.io/docs/scripting.html). Ordinary native serialization and frame scheduling are reusable; the project's authenticated ownership and disconnected-preservation contract require custom integration. These are research references, not incorporated dependencies. Existing engine attribution and unresolved inherited asset terms remain as recorded in the [dependency ledger](dependency-ledger.md). No migration or performance claim follows from this source-only change; build memory usage and actual-core behavior require separate evidence.

The pinned implementation exposes concrete reasons not to reuse ordinary export completion unchanged. `MultiplayerOwnership_PrepareExport` requires an active grant after every load. Ordinary END acknowledges ownership retirement entries, while its watchdog releases the field after 600 emulated frames without commands. Existing trade holds have different settlement rules. Emergency preservation must neither acknowledge a nonexistent host commit nor use a trade opcode as a substitute.

## Optional native contract

The new build alone exports the retained `u32` marker `gMultiplayerEmergencySaveAbiVersion = 1`. The optional manifest fields are `emergency_save_abi_version` and `emergency_save_abi_address`. Existing save ABI, mailbox size and all old opcode numbers remain unchanged. The bridge advertises `Z` followed by little-endian `<HHHH>(1, 19, 21, 10)` only after verification; ordinary public `save_rpc` does not gain offline authority from that marker.

| Opcode | Command and result |
| --- | --- |
| 19 BEGIN_EMERGENCY_EXPORT | Empty data, offset 0, 128 KiB total, positive target revision equal to the launcher's verified base plus one. Requires the exact existing native binding. It permanently holds that core. A safe field with an accepted active grant uses ordinary native serialization and returns the existing 40-byte export metadata. Unsafe admission, absent grant or native save failure returns its error and retains an unsaved hold. |
| 20 PRESERVE_EMERGENCY | Empty data, offset and completed read cursor both 131072. Requires valid frozen bytes. Returns the complete-stream CRC32 and remains held. The caller must durably write and verify the payload and recovery intent before requesting this receipt. It proves neither disk persistence nor host acceptance by itself. |
| 21 QUERY_EMERGENCY | Empty data and offset 0. A 48-byte observation preserves the last mutating command's cached reply and does not consume its sequence. Active observations require the exact original binding, operation UUID and target revision. |

Successful export uses state 2 (EXPORTING) with an emergency latch, allowing the existing 128-byte READ and optional 4096-byte READ_WINDOW. State 9 is EMERGENCY_UNSAVED and exposes no export stream. State 10 is EMERGENCY_PRESERVED after a complete read and preservation request. No emergency path calls `MultiplayerOwnership_Acknowledge`. END, CANCEL, import, grant, BIND and trade controls cannot remove this latch, alter its binding or discard retirement entries. The emergency watchdog never releases it. Exact last-command replay remains idempotent.

The query payload is little-endian: flags at +0; native save state at +4; operation UUID at +8 (16 bytes); original session epoch at +24; incarnation at +28; target revision at +32; read cursor at +36; streamed CRC32 at +40; original failure status at +44. Flags are 1 for an unsaved hold, 3 for valid frozen export, and 7 for preserved export. Inactive observations contain only the current state, with every other payload byte zero. For active observations, binding and cursor fields must agree with the correlated outer response.

## Integration requirements and limits

Fresh Continue needs a durably recorded host allocation and exact native grant acknowledgement before emergency saving is considered armed. The local preservation capability must belong to that same authenticated session and exact bridge object/incarnation; a replacement bridge or core cannot inherit it. Generic server RPC authentication remains required. Missing authority or an unavailable bridge does not justify memory injection, save-file replacement, a new binding or a false success message.

Before host loss, record the original world/player/build/profile, authenticated binding, local canonical base and grant provenance. Preserve complete validated Flash bytes and an immutable operation UUID/hash/base intent under the character lease. Only then request native preservation. The existing closed-start pending-export path can reconcile those exact bytes under a new authenticated host lease; ownership storage already distinguishes historical grant provenance from the current RPC lease. Rejoin must settle that exact operation before canonical installation. A newer head is a conflict to resolve, not permission to rebase frozen bytes.

An already-running ordinary save is outside this first prototype: its existing watchdog can still release after emergency admission is refused. Enabling automatic host-loss handling therefore also requires exact promotion of that original frozen operation or another verified hold strategy. Active trade and native battle requests are rejected without changing their existing holds. A solo battle, script, menu or transition cannot be serialized as an ordinary field save; its core remains unsaved and held. Durable battle reconnection/resumption is a separate implementation and no battle is automatically cancelled, rebound or awarded.

## ABI2 and the dedicated preservation controller

Native commit `44fc27e323b559aab1896a71c1315ceb8b12097e` adds [the promotion patch](../engine-patches/phase7-emergency-promotion.patch) after the isolated ABI1 commit. Its marker is version 2 and its capability is `Z` plus `<HHHH>(2,19,22,10)`. New opcode **22 PROMOTE_EMERGENCY_EXPORT** requires the exact existing binding, UUID and revision. For an ordinary held export it retains the original Flash and RNG, rewinds only the read cursor and CRC, and makes the hold permanent. It never serializes another save or acknowledges ownership. If the ordinary watchdog or a lost END has already left BOUND, it instead enters permanent UNSAVED with an ORDER refusal; it cannot create different bytes under the old immutable transaction. Trade and battle holds remain owned by their original systems. ABI1 manifests remain readable, but the integrated controller requires ABI2.

[EmergencySaveController](../src/emerald_multiplayer/emergency_save.py) reuses the live checkpoint lock, native ownership grant preparation, atomic/fsynced files, validated Flash parser and closed-start exact upload. `arm(expected_revision)` verifies the caller's local revision against the authenticated head, binds the exact bridge, obtains or validates an accepted native allocation, and persists its provenance before registering for loss. The authority is tied to that precise bridge object, session, incarnation and save profile. Replacement bridges, reconnects, guessed current heads, generic `save_rpc` calls and foreign lifecycle tasks cannot inherit it.

On loss, the companion synchronously inhibits automatic reconnect, fails ordinary network requests, and notifies the controller before clearing authentication. The controller drains the existing lifecycle lock. For an idle core it invokes 19; for a known interrupted ordinary export it invokes 22 with the original UUID and base. It reads validated native chunks/windows, checks frozen metadata and ownership/grant provenance, and writes the exact ordinary `pending-export.json` plus 128 KiB candidate before requesting 20. Reopening and comparing the durable files, checking the native CRC receipt and querying the permanent hold all precede a `preserved` result. An existing pending export must match byte for byte. The controller never sends END, CANCEL, import or a new binding with its disconnected authority, and never replaces a live `.sav`. Native serialization can legitimately update the emulator's mapped Flash file.

Only `preserved` sets `can_close=True`. Unsafe scenes, absent grants, disk/transport errors or ambiguous native receipts retain the core as unsaved; pending trades and battles retain their own holds without attempting an ordinary export. Cancellation drains dispatched preservation before propagating. The launcher must keep the runtime lease and owned child alive for every result that does not permit closure. Pre-arm failures and an unavailable native bridge are not successful emergency saves. Process/power loss and resolution of a permanently held unsafe solo scene remain separate limitations.

After validating the exact disconnected authority, even failure to write the initial holding intent triggers a best-effort permanent native freeze under the same task and lifecycle lock. It permits no preservation receipt or closure. This fallback prevents an unavailable disk from silently leaving an otherwise reachable field running offline; an unavailable bridge still cannot be represented as a confirmed hold.

An optional personal-encounter session can drain its exact pre-generation request before opcode 19 through `drain_before_emergency(retained_session)`. The callback runs under the existing owner and lock with a three-second outer bound, and may release only its neutral pre-generation script after a matching native receipt and confirmed safe field. False, timeout or refusal still proceeds to BEGIN's own native safe-point check/permanent freeze. Opcode 22 skips this hook because the ordinary export already owns frozen bytes. The composed reset ABI2/native path needs its separate actual-core qualification; a generic unsafe scene is not made serializable by this hook.

Ordinary checkpoint completion updates the retained verified base. The terminal trade hook records the exact applied/aborted metadata before removing its trade journal, advances that base synchronously and marks the allocation for safe deferred refresh. It permits only an identical terminal retry. A canonical import invalidates the native allocation; until a fresh grant is accepted, host loss may leave an unsaved hold rather than inventing save authority.

[ColdStartRecovery](../src/emerald_multiplayer/cold_start.py) blocks a new core for an incomplete/uncertain emergency journal. A fully receipted candidate is reconciled through the existing exact UUID/base/payload upload under the new authenticated lease. Historical grant provenance remains attached. A different newer head cannot rebase the candidate. Cleanup archives the emergency journal with the ordinary recovery evidence, including recovery after an interrupted journal-removal sequence. No recovery path merges offline progress or resumes a battle.

This extension imports no third-party implementation or new dependencies. The reuse audit rechecked the maintained [RHH serializer](https://github.com/rh-hideout/pokeemerald-expansion/blob/master/src/save.c), official [mGBA scripting API](https://mgba.io/docs/scripting.html) and Python [cancellation shielding](https://docs.python.org/3/library/asyncio-task.html#shielding-from-cancellation). Existing serialization and process/lock ownership were retained; the project's authenticated disconnected authority and immutable recovery receipt require custom composition. These are research references, with attribution still governed by the existing dependency ledger.
