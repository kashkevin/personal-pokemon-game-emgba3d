# Classic Local Soft Reset input — source-only implementation

The owner stopped all testing and requested continued implementation. This change has **not been built or tested**. It changes no accepted ROM, runtime, private preview package, release pin, save, attempt counter or default-off encounter flag. Earlier input-guard and reset proofs cover their frozen sources, not this follow-up.

The existing native first-action request already verifies the original eligible authored encounter, connected session/incarnation, roster epoch, unchanged personal state and battle flags. Its Yes/No confirmation defaults to No and rechecks these conditions before accepting. This implementation reuses that request. Wild encounters, events, unrelated scripts, unsafe scenes and disconnected/unbound characters acquire no reset permission. The next authored encounter still uses the existing durable admission/counting protocol.

`engine-patches/phase6-safe-local-reset-input.patch` is additive to the existing cleanup worktree at `/home/kevin/src/pokemon/engine-admission-cleanup-20261008-1`; its base files are retained separately at `/home/kevin/src/pokemon/reset-input-source-before-1`. It modifies only `src/multiplayer_local_reset.c` and `include/multiplayer_local_reset.h`. The native handler always consumes a complete A+B+Select+Start gesture before `main.c` can reach its BIOS reset branch, then consumes partial releases until all four buttons are up. This guard applies even in default-off builds and before binding. Finishing an encounter cannot rearm a still-held chord. Only an enabled encounter build emits the separate `gMultiplayerResetInputAbiVersion=1` marker; the existing reset admission ABI is insufficient.

`scripts/multiplayer/generate_manifest.py` locates the new marker from the exact ELF and checks the ROM bytes. `reset_mailbox.py` validates the optional paired fields, reset ABI2 prerequisite, alignment, ROM bounds and marker bytes. `bridge_config.py` supplies the verified marker to `bridge/mgba.lua`, which checks the loaded ROM again before opting into the frontend function. The bridge withdraws routing on disconnect or invalid native readiness. No new writable RAM command, host permission, or altered encounter ABI was added.

The SDL adapter registers an mGBA script function using the already-pinned public scripting API. Suppression remains the default. With verified capability, it passes the original complete chord to the native handler; any partial release consumes the remainder. Re-pressing one button, enabling capability midway, or reconnecting while buttons remain held cannot make another request. All four must be released before rearming. This also prevents a brief chord that the native frame never saw from exposing its partial release as an ordinary A/B/Select/Start action. Inputs observed before the complete combination remain ordinary inputs; no input guard can undo an earlier game action.

An old manifest, old native binary, old runtime without the new script function, or default-off native build retains suppression. It does not silently map the combination into Select or enable encounter content. The existing Select route remains available where its native eligibility checks allow it.

The source reuse review follows `docs/windows-controls-audit.md` and `docs/customization-and-reuse.md`. The pinned mGBA SDL input handlers interrupt the core thread around keyboard/joystick key updates, and its scripting callback uses the core thread; the adapter uses those existing serialized entry points. No upstream code/dependency, license, save schema, gameplay probability or balance rule was imported or changed. A pending C helper case records capability, revocation and partial-release expectations; it was deliberately **not executed**. Native default-off/enabled compilation, manifest/Lua integration, ordinary eligible-hunt acceptance, physical input and recovery regression all remain unverified for these new sources.
