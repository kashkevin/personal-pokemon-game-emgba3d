# Development server character arbitration

`WorldServer(..., development_battles=True)` explicitly enables its server-owned native-singles `BattleDesk` adapter. The default is disabled, and the option requires an authenticated ownership store. It creates no battle network endpoint: a trusted controller/router supplies authenticated actor IDs, captured leases and correlated native receipts. Ordinary clients cannot assert a native hold, result, restoration or release through JSON. The existing [native lifecycle](native-battle-desk.md) and [durable local admission](native-battle-admission.md) remain separate components.

Before dispatching any BIND, the trusted coordinator calls `server.battle_desk.authorize_bind(actor, lease, battle_id, generation)`. This synchronous event-loop operation verifies the current connected leases and canonical heads for both participants, rejects either active checkpoint upload or overlapping uncommitted trade proposal, and invokes the original Desk's consent/incarnation checks and intent reservation. Nothing is sent to a ROM here. The first successfully authorized BIND reserves **both** participants, even when only one control was sent or its reply is lost.

While that room remains active with BIND intent, checkpoint begin/chunk/commit/abort, ownership allocation and trade open/offer/confirm/cancel/ACK return `battle_busy`. A third player cannot open a trade with either held participant. Checkpoint metadata and reads, trade status/pending, presence, heartbeat and session-local teams remain available. Other participants may save, allocate IDs and trade independently. This server-wide barrier retains both participants until the complete terminal abort or release acknowledgment barrier archives the room; a first participant's release does not grant early persistent writes.

A challenge before any BIND does not reserve saves or trades. An ordinary checkpoint edit invalidates its captured heads and consent through the existing Desk refresh. The participants can cancel it normally. Partial upload rejection leaves that upload intact so its owner can finish or explicitly abort it. An overlapping trade proposal is preserved rather than silently discarded. Neither refusal consumes a native BIND intent.

Timeout, disconnect, a new lease, partial abort/return or conflicting native data never frees a possible hold. Pre-start uncertainty remains aborting until the required correlated native acknowledgments; after START it becomes recovery-required. Observation with a fresh authenticated lease is allowed, while old lifecycle mutations remain fenced. No forfeit, reward, result or automatic gameplay release is selected by this component.

This remains development integration. The Desk and server reservations are session-local; a new host process cannot reconstruct them from this adapter alone. The durable local intent currently prevents a client relaunch but has no settlement API. Player-facing delivery still requires durable authoritative battle recovery, cross-client controller wiring and the owner's interruption/result policy. The underlying store is an internal trusted authority, and direct administrative store writes or a separately constructed Desk bypass this server boundary. All runtime calls to this adapter must remain on its owning event loop.

The integration tests use four authenticated TCP actors, genuine encrypted Flash fixtures and real SQLite transactions. They exercise both-party reservation before native ACK, controlled RPC errors without disconnect, heartbeat/presence/read continuity, independent paired trading and checkpointing, pending upload/trade conflicts, prebind head edits/cancellation, partial abort/release barriers, disconnect/rejoin and sticky post-start expiry. Native receipts are simulated trusted inputs; these tests do not establish an actual game battle or four-ROM acceptance.

On October 8, the 12 new integration tests and the affected server/checkpoint/ownership/trade/team/Desk group passed on both Windows and WSL: 95 tests per system, zero skips. An independent source review found no scoped admission/release bypass.
