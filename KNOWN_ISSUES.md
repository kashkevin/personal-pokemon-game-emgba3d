# Known issues

Confirmed problems only. Severity: Blocker / High / Medium / Low.

## Native PC build (branch `claude/native-pc`)

| ID | Severity | Issue | Reproduction | Status |
| --- | --- | --- | --- | --- |
| N1 | High | Crash in Professor Birch's intro: `Task_HandleMonAnimation` read `gBattleStruct` (NULL outside battle). Harmless on the GBA (reads BIOS), fatal natively. | New game, advance Birch's speech until Lotad appears. | Fixed with `NATIVE_NULL_GUARD` (`src/pokemon_animation.c`). |
| N2 | High | Naming screen sprite and VBlank callbacks ran one frame after the screen data was freed (7 NULL accesses). | Confirm the player's name. | Fixed: callbacks return when the data is gone (`src/naming_screen.c`). |
| N3 | High | Menu cursor (▶) invisible and stray glyph pieces ("NO" showed as "NOI"); text at tile-aligned positions was also drawn into the next tile. Cause: `1 << 32` and `x >> 32` in the glyph copy, 0 on ARM but unchanged on x86. | Any YES/NO or list menu. | Fixed with `ARM_LSL32`/`ARM_LSR32` in `src/text.c`. Re-checked 2026-10-09: start menu cursor and save YES/NO correct. |
| N4 | Medium | The RHH "Powered by" logo in the intro looked corrupted. Cause: the Linux build used the "fast draw" GBA renderer, which draws every text background as 16-colour; this screen uses a 256-colour background. Decompression is not involved: all 7469 compressed assets decode correctly natively (`check-decompress`). | Launch; first intro screen. | Fixed: Linux now uses the same "easy draw" renderer as the Windows build (`Makefile_pc`). Visual re-check pending. |
| N5 | High | Every player would get the same Trainer ID and RNG seed: the GBA hardware timers used for seeding do not run natively. | New game. | Fixed: host-clock entropy seeds the RNG (`Platform_GetEntropy32`). |
| N6 | Medium | The game's own soft reset (`DoSoftReset`, used by the clear-save screen, credits, save-failure screen and others) exited the program. | Title screen, hold B+SELECT+UP, answer NO. | Fixed: in-process reset (`src/platform/game_memory.c`) restores all game memory to its boot state and restarts the game thread; window, audio, save image and clock survive. Verified on Linux: the intro restarts, the process stays up, the save file is unchanged. Note: in this build the A+B+START+SELECT chord (and Ctrl+R, which sends it) belongs to the multiplayer Local Soft Reset handler and never reboots, by design. |
| N7 | Medium | Integer division by zero crashes on x86 but returns a value on the GBA. | Any such code path (none seen yet in play). | Mitigated at runtime by `fault_compat.c`; sites are logged and must be fixed in source (the compiler may still mis-optimise them). |
| N8 | Low | `src/platform/bios.c` contains code derived from VBA-M (GPL-2.0+) and mGBA (MPL-2.0). | — | Open: replace with an independent GBATEK-based implementation or comply before giving the build to anyone. |
| N9 | High | New game on an empty save crashed at random natively. An erased flash sector reads id 0xFFFF, which indexed the 14-entry save-location table far out of bounds (`CopySaveSlotData`; corrupt ids in `GetSaveValidStatus` likewise). Harmless stray read on the GBA; a fault natively whenever that address is unmapped. | Start with no save file (failed about 1 run in 2). | Fixed: such sectors are treated as invalid (`src/save.c`, PORTABLE only). |
| N10 | Blocker | New game hung at the move into the truck. The synchronous map loader (`DoMapLoadLoop`) busy-waits for DMA3 requests that the GBA's VBlank interrupt drains during the loop; natively interrupts only run between frames. | Finish Birch's intro. | Fixed: `Platform_SpinWaitForVBlank` lets the frame end when a poll keeps spinning within one frame (like a GBA lag frame); callers that poll once per frame are unaffected (`src/bg.c`, `src/platform/sdl2.c`). |
| N11 | High | Wild battle start crashed natively: the "slice" battle transition's VBlank callback ran once more after the transition data was freed (NULL reads; harmless on the GBA, the screen is already black). Found by the NULL trap. | Walk into a wild Pokémon. | Fixed: after release the transition callbacks read a zeroed stand-in (`src/battle_transition.c`, covers all transition types). |
| N12 | Medium | Assembler-built script data was writable natively (it is ROM on the GBA), so it was outside the soft-reset memory and a stray write would silently change a script. | — (found by `check-game-sections`). | Fixed: script data is read-only natively (`tools/pc_port/asm_to_x86.sed`); `make -f Makefile_pc check-game-sections` fails if any game object keeps a writable section outside the reset memory. |
| N13 | High | Opening the Pokédex crashed natively. `CreatePokedexList`'s Hoenn loop runs one entry past the Hoenn dex (`HoennToNationalOrder(HOENN_DEX_COUNT)` returns 0, an upstream off-by-one), and `GetSetPokedexFlag(0, ...)` then reads index 0x1FFFFFFF. A stray read on the GBA. Found by UBSan. | Start menu, POKéDEX. | Fixed natively: dex number 0 or out of range reads as "not seen/caught" and is never written (`src/pokedex.c`). Upstream bug; GBA build unchanged. |
| N14 | High | Pokédex list: `UpdateSelectedMonSpriteId` reads `gSprites[0xFFFF]` before checking for 0xFFFF (vanilla code). Megabytes out of range natively. Found by UBSan. | Pokédex, open an entry. | Fixed natively by testing the id first (`src/pokedex.c`). |
| N15 | Medium | Summary screen passes `WINDOW_NONE` (255) to `PutWindowTilemap` for windows it never added (vanilla code); the GBA reads unrelated memory as a window, natively that memory differs and could draw garbage. Found by UBSan. | Party menu, SUMMARY, change pages. | Fixed natively: window tilemap calls ignore invalid ids (`src/window.c`). |
| N16 | Low | The overworld time-of-day form check computed battle party state from `gBattleStruct` while it is NULL (outside battle); natively only an optimisation kept it from reading address ~NULL. Found by UBSan. | Walk around (runs every frame). | Fixed natively: no battle party state outside battle (`src/pokemon.c`). |
| N17 | High | Windows build: MinGW uses the MSVC struct layout by default (bit-fields not packed across types, 8-byte members 8-aligned), which breaks save compatibility; the engine's own static asserts failed. | Build the .exe without the flags. | Fixed: `-mno-ms-bitfields -mno-align-double`; `abi_layout.py` now also checks the Windows layout (172 types match). |
| N18 | Medium | Windows build: assembler "read-only" data (`.rodata`) was linked into a writable section of its own. | `objdump -h pokeemerald-mp.exe`. | Fixed: converted to `.rdata` (read-only) on Windows; `check-game-sections` passes on Windows. |
| N19 | Medium | Windows build: `RandomUniform` and three other functions are weak aliases, which MinGW does not resolve (link failure); `gTestRunnerEnabled` is weak data. | Link the .exe. | Fixed natively: plain functions/data (`src/random.c`, `src/test_runner_stub.c`). |
| N20 | High | Windows (Wine): one crash during the intro after loading a save, in about ten launches; not reproduced since. Cause unknown. | Launch with a save; unknown trigger. | Open. `crash.log` reporter added (`src/platform/crash_report.c`); watch for a recurrence. |
| N21 | Info | Title screen B+SELECT opens the Berry Program Update, which waits for a link cable forever natively, exactly as on a GBA with no cable attached. | Title screen, hold B+SELECT. | By design (vanilla); close the game to leave. |
