## GBA ROM identity guard

While native-port changes are `PORTABLE`-only, the GBA ROM must stay identical to
the baseline: `pokedev.gba` sha256
`f214735b64e113fd10730eacca5764d757f2c93a3685230aa905af7a7cdd3387`. Last confirmed
on 2026-10-11 for engine `d799c4a8a` and `d72d32c09` (the graphics overhaul's
phases 2-4, `pokeemerald.gba` rebuilt from each); before that for `cb859b10c`
(phase 1) and `6743bc1e5` (its first step); before that for
`b86ea813a` (the resolution work) and `1579e7fd8`
(`claude/native-pc`, with the crash fixes of the battle branch) and `edd1f5105`
(`claude/native-graphics`); before that for
`edb755a26`, `8920f1f67`, `b752d8e48` (`claude/battle-3d`) and `732fbef43`
(`claude/battle-3d-integration`, which contains `3e39f2b15`); re-check before every
native checkpoint.

## Rollback

* To the emulator game: restore `emulator-baseline-20261009` (see
  `docs/native-migration/baseline.md`). Codex's packaged Windows runtime and release
  candidates in the Codex LocalCache `PokemonPrivate\artifacts` folder are untouched.
* The native launcher package (from `native-wip-20261010-4`) keeps its worlds and
  characters in `%LOCALAPPDATA%\PokemonPrivate\launcher` (where any launcher
  package started outside Codex keeps them; empty on the owner's PC before this
  checkpoint). It changes neither the emulator runtime, the emulator-baseline
  checkpoint nor Codex's folders.
* Native work: each `native-wip-*` tag is a rollback point on `claude/native-pc`;
  `graphics-wip-*` tags are rollback points on the engine's `claude/native-graphics`
  (the 3D renderer work, kept off the stable native branch until it reaches parity).
