# Pokémon Emerald private multiplayer

This project targets a private adventure for one to four players total using Emerald as its foundation, with independent exploration and saves, Gen 1–6 Pokémon, Gen 6 mechanics including Fairy, 18 starters, and all eligible officially released Mega Evolutions, including later additions.

Current checkpoint: **four actual clients, recoverable paired trades, and a bundled native Windows runtime.** Four Emerald cores passed 30 checks covering remote players, independent maps/menus/encounters, disconnect/rejoin, individual checkpoints and fresh Continue. Two-core trade proofs cover exchange, lost confirmation/server restart, one-sided preparation cancellation, and closed-game recovery before Continue. The Windows runtime has loaded the correct owned character through the verified startup/save-lock lifecycle. [Four-client evidence](docs/four-player-foundation.md), [trade evidence and limits](docs/trade-foundation.md), [Windows runtime](docs/windows-runtime.md).

The latest complete Python regressions passed **604 tests on Windows and 616 on WSL, without skips**. The Windows run preceded twelve new 2v2 consent/arbitration cases; those passed in a subsequent **82-test affected group on both systems**, and the WSL full run includes them. The service now requires each of four trainers to consent separately and reserves all four characters until every required abort or release acknowledgment arrives. Actual full-six-per-trainer 2v2 gameplay and interruption recovery remain in development. [Consent/lifecycle service](docs/native-battle-desk.md), [server arbitration](docs/native-battle-arbitration.md), [transport and regression record](docs/native-battle-transport.md), [durable admission guard](docs/native-battle-admission.md).

The frozen native singles ROM passes **5,465 engine tests with zero unexpected failures**, retaining the baseline's 18 known failures, 421 TODOs and nine expected failures. An actual native 1v1 completed moves, fainting, switching, exact party/RNG restoration and fresh Continue. A four-core repeat also verified the other two players' independent movement, menu use and checkpoint during that battle. The new ABI3 engine has now completed an **actual four-core 2v2 with starter parties**, followed by exact personal restoration, independent checkpoints and fresh Continue on all four. Its 1v1 compatibility run also passed. Full-six gameplay, broader battle coverage and interruption recovery remain required. [Native singles proof](docs/native-singles-proof.md), [four-core Multi proof and limits](docs/native-full-multi.md).

An opt-in [autosave scheduler](docs/autosave-foundation.md) now handles safe admission, session changes and uncertain saves. Its [read-only save window](docs/save-window.md) and verified CRC optimization reduced a paced checkpoint from 39.254 to **6.328 seconds**; ordinary native saving accounts for most remaining delay. Automatic scheduling stays disabled in the normal runtime pending further [performance and Windows qualification](docs/save-performance.md). Pinned TLS and [host/account invitation provisioning](docs/host-provisioning.md) are implemented separately. A default-off [local reset test encounter](docs/local-soft-reset-design.md) passed two-core and four-core tests for cancellation, a fresh roll, ordinary capture, saving/recovery and fresh Continue while other players continued independently. Its separate frozen engine source passes **5,458 engine tests with zero unexpected failures**. Production reset encounters and Windows input, native trade effects and player menus, the Host/Join interface, import/patch packaging, and separate-PC LAN/Internet acceptance remain required before this becomes a friend-ready download. These foundations do not claim the full content backlog is complete.

Existing content requirements remain in scope.

Original briefs and all amendments remain preserved verbatim.

The requested delivery is a downloadable Windows game with **Host Game / Join Game**, for four players total including the host. The owner's PC hosts over home Wi-Fi, with direct Internet connections through port forwarding. Friends should need no compiler, Python installation, VPN, or manual emulator script setup. [Local PC setup](docs/local-pc-setup.md) records the packaging target, hosting setup, and development downloads. The [Host/Join session backend](docs/launcher-session.md) now reuses authenticated TLS, installation pins and the protected runtime lifecycle; its 63 affected tests passed on Windows and WSL. It supports existing enrolled characters. The visible interface, first-character setup and complete player package remain in development.

The baseline is RHH `pokeemerald-expansion` at `expansion/1.17.1`, commit `bb1093a7c72d3961d9a37d8e02ad2abc2c866682`, built in Ubuntu 24.04 under WSL2. The [build record](docs/baseline-build.md) records versions, artifacts, and acceptance status; the [dependency ledger](docs/dependency-ledger.md) records provenance. The Lua bridge, companion, allocated ROM mailboxes, remote-avatar adapter, durable storage, live checkpoints and ownership are implemented. Trade recovery is verified; native trade effects and the player interface still require integration and actual-game acceptance.

Development must preserve small commits, repeatable tests, and known-good checkpoints. `RESEARCH_FOUNDATION_V1` records documentation only. The engine's `BASELINE_BUILD` preserves the accepted unchanged source, `MULTIPLAYER_POC` records local movement, and `DURABLE_CHECKPOINT_POC` records closed-game save recovery. `LIVE_CHECKPOINT_POC` records live save/recovery, and `OWNERSHIP_FOUNDATION_POC` records the verified ownership slice in both repositories. `NATIVE_SINGLES_POC` records the qualified native battle slice and its explicit limits. The engine's `LOCAL_RESET_DEV_POC` pins the separate first-action development encounter and its bounded proof. Private build artifacts and save evidence remain archived.

ROMs, player saves, server databases, and private backups are excluded from Git. No ROM download or distribution is part of this repository.
