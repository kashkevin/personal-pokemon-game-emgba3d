# Pokémon Emerald private multiplayer

This project targets a private adventure for one to four players total using Emerald as its foundation, with independent exploration and saves, Gen 1–6 Pokémon, Gen 6 mechanics including Fairy, 18 starters, and all eligible officially released Mega Evolutions, including later additions.

Current checkpoint: **verified two-player movement and live save/recovery.** Two actual Emerald cores render each other and move independently. Authenticated, revisioned checkpoints now support live ROM export and canonical recovery while the other player continues moving. Two full runs on the final build passed 12 checks each, including interrupted staging, invalid imports, fresh Continue, and native game reboot/rebinding. Windows GUI/LAN delivery, four actual game clients, and Pokémon ownership transactions remain ahead. [Movement evidence](docs/phase2-presence.md), [durable storage](docs/phase3-checkpoints.md), [live checkpoint evidence and limits](docs/phase3-live-checkpoints.md).

Read [the current master specification](docs/master-spec.md) for the accepted gameplay and phase order, [the technical foundation](docs/technical-foundation.md) for the stack and architecture, and [the Gen 6 foundation audit](docs/gen6-foundation-update.md) for configuration requirements and later Mega adaptations. [The original brief](docs/project-brief.txt), [Generation 6 update](docs/project-update-gen6.txt), and [Local Soft Reset amendment](docs/project-update-local-soft-reset.txt) are preserved verbatim. The reset feature remains [queued behind the multiplayer foundations](docs/local-soft-reset.md); other game rules and phase priorities are unchanged.

The requested delivery is a downloadable Windows game with **Host Game / Join Game**, for four players total including the host. The owner's PC hosts over home Wi-Fi, with direct Internet connections through port forwarding. Friends should need no compiler, Python installation, VPN, or manual emulator script setup. [Local PC setup](docs/local-pc-setup.md) records the packaging target, hosting setup, and development downloads. The player package remains future work; the current server is a development presence and checkpoint prototype.

The baseline is RHH `pokeemerald-expansion` at `expansion/1.17.1`, commit `bb1093a7c72d3961d9a37d8e02ad2abc2c866682`, built in Ubuntu 24.04 under WSL2. The [build record](docs/baseline-build.md) records versions, artifacts, and acceptance status; the [dependency ledger](docs/dependency-ledger.md) records provenance. The Lua bridge, companion, allocated ROM mailboxes, remote-avatar adapter, durable storage, and explicit live checkpoint prototype are implemented. Stable Pokémon ownership identities and mutation hooks are the next Phase 3 step before trade transactions.

Development must preserve small commits, repeatable tests, and known-good checkpoints. `RESEARCH_FOUNDATION_V1` records documentation only. The engine's `BASELINE_BUILD` preserves the accepted unchanged source, `MULTIPLAYER_POC` records the local movement prototype, and the project checkpoint `DURABLE_CHECKPOINT_POC` records closed-game save recovery. Private build artifacts and save evidence remain archived.

ROMs, player saves, server databases, and private backups are excluded from Git. No ROM download or distribution is part of this repository.
