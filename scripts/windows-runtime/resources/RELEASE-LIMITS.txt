Emerald Together — development preview limits

This is a private development package for up to four players. It is not the
completed game. README.txt states whether this exact package can import a
matching owner-supplied dump. Packages without a verified release patch keep
Import my game disabled and cannot prepare a new friend's installation yet.

The launcher includes Host Game / Join Game, local host world and character
setup, separate friend invitations, five-minute autosave, launcher Save now,
and an encrypted connection check. Autosave is on by default; its toggle is
remembered for this character and world on this PC. It waits for a safe field
location. Save now works with autosave off. First character setup requires
ordinary New Game, starter selection and native Save, followed by explicit
host enrollment.

The native Players menu and multiplayer services have separate acceptance
records. A battle invitation or accepted team is not a completed battle.
Native battle handoff and mutual trade confirmation have been implemented,
but complete battles, trade effects and interruption recovery still need their
remaining playable acceptance. Campaign and customization work remains.

The host can retain durable reservations for interrupted multiplayer battles.
When it reports an unresolved battle, the launcher blocks a fresh game session,
including after a host restart. This preserves the waiting state and prevents
ordinary play from bypassing recovery; it does not resume or clear the battle.

The accepted host-loss behavior is to save and disconnect each player, and an
interrupted multiplayer battle must wait for every participant to reconnect.
This build includes emergency preservation for a safe field location or an
ordinary save already in progress. The launcher keeps the exact local save
until it can reconcile it with the host on rejoin. Unsafe scenes can remain
held without a completed save; keep the game open when the launcher reports
that recovery is needed. Interrupted multiplayer battle resumption remains
unavailable in this build. Automatic and manual checkpoints normally require
a reachable host. Keep private recovery files when an operation is uncertain.
Use the launcher's Save now and wait for its success message before closing;
the game's own Save menu and window closure do not confirm a host checkpoint.

Windows runtime checks passed the full five-minute autosave interval, separate
per-player toggles, manual saving and fresh Continue. A source-launched window
also passed Host Game, the autosave checkbox, Save now and reopen. The standalone
packaged buttons and complete visible New Game-to-enrollment flow still need
their own checks. Headless game checks passed host loss in a safe field and
partway through an ordinary save; Windows host-loss interaction, pause comfort,
physical keyboard, audio and gamepads remain unverified.
The desktop automation helper's ordinary keys did not produce the SDL button
events needed for gameplay. Hardware keyboard failure has not been established.

Clean-machine installation, full-game BPS import, accessibility, four separate
Windows PCs, Wi-Fi, port-forwarded Internet, latency/loss and reconnect behavior
remain separate acceptance checks. A successful Check connection verifies the
invited TLS endpoint only; it sends no player login and proves no remote path.

The download contains no game ROM, player save, world database, host certificate
or personal invitation. Keep each friend's invitation separate from the ZIP.
Exact component pins and source hashes are in _internal/package-provenance.json;
license notices and native source/relink material are under _internal.
